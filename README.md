# Signal Commons Studio

Signal Commons Studio is an offline-first React workspace for community soundscape fieldwork. Field researchers curate short recordings, route editors arrange clips into listening sites, reviewers resolve consent and transcript findings, and teams compare listener scenarios before exporting a study snapshot.

## Run locally

```bash
npm install
npm run dev
```

Open `http://127.0.0.1:4173`. The study is persisted in browser local storage under `signal-commons.workspace.v1`; the storage key is retained for compatibility while stored documents migrate to the current schema. A checksummed previous record is retained under `signal-commons.workspace.backup.v1` for recovery, and committed changes synchronize across open tabs. No network services or environment variables are required. Use the sidebar **Reset sample study** action to restore the built-in study.

## Validation commands

```bash
npm run build      # TypeScript + production build
npm run test       # Vitest unit tests
npm run test:e2e   # Playwright smoke workflow checks
npm run check      # build + unit + smoke e2e
npm run gate       # build + unit + smoke e2e + full chaos drill gate
```

## Chaos drill environment

The chaos drills extend validation with repeatable **concurrency**, **failure
recovery**, and **large-volume** scenarios. Every drill operates an isolated
Chromium profile, seeds deterministic data, injects a real fault, asserts a
recovery invariant, and cleans up after itself. Drills can run individually,
per suite, or as one release gate, locally and in CI with the same command.

### One-time setup

```bash
npm run bootstrap:chaos
```

This installs dependencies and Chromium. If the machine grants root it uses
Playwright's system packages; otherwise it downloads the required Chromium
libraries into a user-owned prefix (`~/.cache/playwright-local-libs`) and the
`drill` scripts pick them up automatically — no system mutation, removable by
deleting that directory.

### Running drills

```bash
npm run drill                 # full gate: all 13 scenarios, serial, no retries
npm run drill:one -- CC-02    # one scenario (or any grep pattern)
npm run drill:suite -- @recovery    # one suite: @concurrency | @recovery | @scale
npm run drill:report          # print the last gate report; exits non-zero on failure
npm run clean:drill           # remove generated reports and drill artifacts
```

Scenario IDs are stable and suitable for CI allow/deny lists:

| Suite        | IDs            | Coverage                                                        |
|--------------|----------------|-----------------------------------------------------------------|
| Concurrency  | `CC-01`–`CC-03` | multi-tab commits in revision order, stale-write refusal, event idempotency |
| Recovery     | `FR-01`–`FR-07` | abrupt tab kill, corrupt/truncated primary, total corruption, reference repair, release survival, storage outage |
| Large volume | `LD-01`–`LD-03` | 1,200-clip library interactivity, bulk placement, readiness at scale |

### What gets reported

After a run, `chaos-report/` contains:

- `chaos-report.json` — machine-readable gate artifact (totals per suite,
  per-scenario status, fault, guarantee, business impact, failure stage and
  location).
- `chaos-report.md` — readable report with the injected fault, the invariant,
  the business impact of a regression, and the exact failing step plus a code
  snippet.
- `playwright-results.json` and `html/` — raw Playwright results and trace UI.
- On failure, `test-results/chaos/` keeps a trace, screenshot, and video per
  drill so a failed gate is diagnosable without reproducing it.

The gate runs single-worker with zero retries on purpose: a timing-sensitive
flap must fail loudly rather than be hidden by a retry.

### Determinism, isolation, and cleanup

- **Deterministic:** drill studies are generated by `e2e/chaos/fixtures.ts`;
  every id, timestamp, and value derives from an index — no wall clock or
  randomness in app data — so two runs produce identical studies and verdicts.
- **Isolated:** each test gets a fresh in-memory browser context; workspace
  storage keys are purged before and after every drill; nothing touches real
  browser profiles, the host filesystem, or network services.
- **Cleanable:** faults are confined to the page/context; the local library
  prefix and `chaos-report/` / `test-results/chaos/` directories are the only
  external artifacts, and `npm run clean:drill` removes the generated ones.


## Directory structure

- `src/domain`: recording models and validation, route analysis, review transitions, release rules, checklist serialization, and listener projections.
- `src/state`: typed commands, revision guards, reducer, versioned migrations, audit log, cross-tab synchronization, checksummed persistence, seed study, and undo history.
- `src/features/library`: searchable signal library and validated recording editor.
- `src/features/route`: listening-site planning, placement transitions, and constraint feedback.
- `src/features/quality`: evidence finding lifecycle, site field checklists, release gate, and snapshot export.
- `src/features/scenarios`: non-mutating listener scenario controls and derived metrics.
- `src/components`: shared shell, navigation, forms, badges, metrics, dialogs, and visual primitives.

## Inputs and outputs

- Recording entries accept a catalogue ID, title, recorder or source, recording date, file format, capture location, audio specification, signal role, sensitivity, transcript status, consent status, tags, and listening summary.
- Quality findings accept severity, owner, optional site or clip links, and decision context.
- A successful release check enables a JSON file named `signal-commons-snapshot-YYYY-MM-DD.json` containing the study, recordings, listening sites, summary metrics, and unresolved non-blocking findings.
- Selecting a listening site on the quality desk shows a field recording checklist that can be downloaded as CSV.

State-changing page actions call typed workspace commands. Commands validate at the boundary, enforce route capacity, carry revision guards, dispatch reducer events, and persist a checksummed recoverable record. Repeated commands are idempotent, stale revisions are rejected, and committed changes synchronize across tabs. Readiness checks freeze a revision, deterministic study fingerprint, and release lineage; later changes mark the frozen release stale. Derived route and scenario analysis is pure and recalculates without mutating saved data.
